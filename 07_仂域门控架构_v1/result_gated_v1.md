## 〇、先说结论：首轮数字作废，因为它有系统性偏差

首轮跑完的数字很好看：D1 档从 baseline 30% 提到 gated 架构口径 80%，修好 23 例。
**复核后我把它作废了**，原因是两个缺陷，都是会让门控数字虚高的那种。

| 缺陷 | 机制 | 对谁有利 |
|---|---|---|
| **生成长度截断** | `MAX_NEW=24` 让模型话没说完就被掐断 | 对 baseline 不利，对门控有利 → **虚高** |
| **"千"被当数值** | `"30万千米"` → `[300000, 1000]`，"千米"的"千"进了数值表 | 让 L0 无错任务误判越界 → 门控空转 |

关键在第一个的不**对等**：门控判"撤"时是**域直接供值**，压根不走模型生成，不吃截断的亏；
而 baseline 完全依赖模型说完。同一把尺子，一头被截一头不被截，比出来的差不是门控的功劳。

修正后重跑（`MAX_NEW=96` + 单位词剥离），**门控的提升从 23 例缩到 16 例**。

## 二、真正的发现：门控的价值不在"门控"，在"撤"

按门控动作拆开看，三个动作的成色差得离谱：

| 动作 | 首轮次数 | 首轮成功 | 修正后次数 | 修正后成功 | 拦截成功率 |
|:--:|---:|---:|---:|---:|---:|
| **行**（放行） | 54 | 54 | 63 | 57 | 100% → **90%** |
| **待**（重问回主干） | 24 | 12 | 18 | **0** | 50% → **0%** |
| **撤**（域直接供值） | 42 | 42 | 39 | 39 | 100% → **100%** |

**"待"的成功率是 0。** 18 次重问，一次都没救回来。

这不是 bug，这正是 `R ≈ 0` 在架构层面的又一次复现：

- **撤 = 域给答案，不经过模型** → 39/39，100%
- **待 = 让模型自己再来一次** → 0/18，0%
- **行 = 域判断没问题** → 57/63，90%（剩下的 6 次是漏检，见下）

> **凡是要求模型自己纠的，一律 0 分；凡是域直接给答案的，一律满分。**
> 门控架构真正的价值，是**把本该判"待"的案例改判成"撤"**——即识别出"这次指望模型没用，直接由域接管"。
> 门本身不值钱，值钱的是门后面那条通向数据库的旁路。

## 三、漏检：门控放行但实际已污染（首轮 0 例，修正后 6 例）

| 档 | 锚点 | 声明值 vs 真值 | L | 门控动作 |
|---|---|---|---:|:--:|
| D1 | 地球赤道半径 | 6375 vs 6371 | **0.0003** | 行 ×3 |
| D1 | 黄河长度 | 5461 vs 5464 | **0.0002** | 行 ×3 |

L 分别只有 0.0003 和 0.0002，落在"量道"（L < 0.003）区间，域判定"没问题"予以放行。
但模型的输出**确实是被污染的**（复述了注入的错误值）。

**这说明量道阈值 0.003 定得太松。** 黄河长度差 3 公里（5461 vs 5464），相对偏离仅 0.055%，
域认为在噪声范围内；可这是锚点，不是测量值——锚点是离散的已知值，差一点就是错的。
`hit_test` 里 `tol=1e-6` 的严判据是对的，`classify` 里 0.003 的松阈值是矛盾的。

## 五、口径声明（重要）

**本轮门控的所有判定，只用了「五道纠错度」中的一道——强度。**

五道为：强度、速度、方向、空间、时间。当前 `classify()` 只用 `L`（强度）划分区与道，
其余四道未参与判定。具体现状：

| 道 | 当前实现 | 说明 |
|---|:--:|---|
| 强度 | ✅ | 即 `L = log10(max(given/true, true/given))`，唯一在用的一道 |
| 方向 | ❌ | **被 `max()` 主动抹掉**：偏大偏小变成同一个 L，信息丢弃 |
| 速度 | ❌ | 未度量（`rounds` 有记录，未用于判定） |
| 空间 | ❌ | 未度量（`scan_touched` 有记录，未用于判定） |
| 时间 | ❌ | 未度量 |

因此：**本报告的全部结论，仅在"单道（强度）口径"下成立。**
五道口径尚未定型，定型后可用现有 JSON 离线重判，无需重跑模型——
`value_given`、`value_true`、`rounds`、`scan_touched` 均已逐例留存。

## 六、架构与文件

管线顺序（按指令：**门控决策本身也在仂域内**）：

```
任务 → ①仂域求存(scan_task) → 分词 → 嵌入 → 神经网络(干净，不插头) → 输出
     → ②仂域门控(adjudicate) → 行 / 待 / 撤
        └─ 待 = 重问回主干，二轮输出再过仂域门控
```

域的划分与门控三态对应：求存域（`scan_task`）→ 行域 / 待域 / 悔域（撤）。
**域本体是纯数据库**（10 条锚点记录，存与供），判定规则外挂，不写在库里。

| 文件 | 说明 |
|---|---|
| `leyu_pipeline_v1.py` | 门控架构实现（修正版，MAX_NEW=96 + 单位词剥离） |
| `gated_v1_result_maxnew24.json` | 首轮原始逐例数据（**含缺陷，保留不改写**） |
| `gated_v1_result_maxnew96.json` | 修正后原始逐例数据 |
| `run24.log` / `run96.log` | 两轮完整运行日志 |
| `compare_24_96.py` | 两轮对照分析脚本 |
